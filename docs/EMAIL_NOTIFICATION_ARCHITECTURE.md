# Grand Bandhan — Centralized Event-Driven Email Notification Architecture

## 1. Architectural Overview & Design Principles

Grand Bandhan employs an **Event-Driven Transactional Outbox Pattern** for all client, agency, and vendor communications. 

Critical business workflows—such as agency onboarding approval, enquiry planner assignments, bespoke proposal delivery, booking confirmations, and payment receipts—automatically emit structured events that are formatted into high-luxury HTML emails and persisted directly in **Neon PostgreSQL** under the `EmailLog` table.

```
 Business Action
(e.g., Agency Register, Proposal Sent, Payment Recorded)
         │
         ▼
NotificationService.emit(NotificationEvent, Payload)
         │
         ├───► 1. Check User Notification Preferences (Optional Categories)
         │
         ├───► 2. Render Imperial Navy & Gold HTML Email Template
         │
         ├───► 3. Write to Neon PostgreSQL EmailLog (Status: SENT / QUEUED)
         │
         └───► 4. Dispatch via Resend REST API (https://api.resend.com/emails)
```

## 2. Event Catalog (`NotificationEvent`)

All 28 system notification triggers are enumerated in `apps/api/src/modules/notifications/notification.types.ts`:

### 2.1. Agency Onboarding & Governance
- `AGENCY_REGISTERED`: Dispatched to agency owner upon application submission.
- `AGENCY_APPROVED`: Dispatched to agency owner when Super Admin approves the workspace.
- `AGENCY_REJECTED`: Dispatched with reason if compliance verification fails.
- `AGENCY_SUSPENDED`: Dispatched if an agency account is frozen.

### 2.2. Enquiry & Customer Intake
- `ENQUIRY_RECEIVED`: Dispatched to customer with their reference code (`GB-ENQ-YYYY-XXXX`).
- `ENQUIRY_ASSIGNED`: Dispatched to wedding planner with couple parameters and contact details.
- `ENQUIRY_STATUS_CHANGED`: Dispatched on status transitions.

### 2.3. Wedding Proposals
- `PROPOSAL_SENT`: Dispatched to couple with estimated budget, scope, and digital response link.
- `PROPOSAL_ACCEPTED`: Dispatched to agency admin and assigned planner when couple accepts.
- `PROPOSAL_REJECTED`: Dispatched with couple's feedback if declined.
- `PROPOSAL_REVISION_REQUESTED`: Dispatched when modifications are requested.

### 2.4. Weddings & Day-of Timeline
- `BOOKING_CONFIRMED`: Dispatched to couple upon formal project creation with wedding code.
- `CONTRACT_SIGNED`: Dispatched when digital agreement is executed with IP verification.
- `EVENT_SCHEDULE_UPDATED`: Dispatched to vendor roster on live timing shifts.
- `VENDOR_ARRIVAL_VERIFIED`: Dispatched when coordinator logs on-ground arrival.

### 2.5. Financial Milestones & Settlement
- `PAYMENT_MILESTONE_CREATED`: Dispatched when booking deposit or milestone schedule is published.
- `PAYMENT_RECEIVED`: Dispatched to couple with official transaction receipt.
- `PAYMENT_OVERDUE`: Dispatched for pending milestones past their due date.
- `SETTLEMENT_FINALIZED`: Dispatched to agency director and couple for final account closing.

### 2.6. Identity & Security
- `PASSWORD_CHANGED`: Dispatched when an account password hash is updated.
- `USER_INVITED`: Dispatched to newly created staff planners or coordinators.

## 3. Transactional Outbox Schema (`EmailLog`)

Every email attempt is recorded on Neon PostgreSQL for complete auditability:

```prisma
model EmailLog {
  id                String              @id @default(uuid())
  agencyId          String?
  agency            Agency?             @relation(fields: [agencyId], references: [id], onDelete: Cascade)
  recipientEmail    String
  recipientName     String?
  recipientRole     String?
  eventType         String
  subject           String
  templateName      String
  status            EmailDeliveryStatus @default(SENT)
  providerMessageId String?
  errorMessage      String?
  retryCount        Int                 @default(0)
  relatedEntityType String?
  relatedEntityId   String?
  sentAt            DateTime?
  createdAt         DateTime            @default(now())
}
```

### Delivery Statuses
- `QUEUED`: Stored in outbox, awaiting transmission.
- `SENT`: Dispatched to Resend API.
- `DELIVERED`: Confirmed by email delivery provider webhook.
- `FAILED`: Transmission error; error message logged, eligible for retry.
- `BOUNCED`: Recipient inbox rejected message.

## 6. Notification Monitoring & Governance Endpoints

- **`GET /api/notifications/logs`**:
  - Scoped to tenant (`SUPER_ADMIN` views global outbox; `AGENCY_ADMIN` views agency outbox).
  - Filterable by `status`, `eventType`, `recipientEmail`, and date range.
- **`GET /api/notifications/health`**:
  - Returns total sent, delivered, failed count, and outbox delivery rate percentage.
- **`POST /api/notifications/logs/:id/retry`**:
  - Re-triggers dispatch for any failed email and increments `retryCount`.
